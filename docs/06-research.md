## 1. Unipile LinkedIn API

Unipile is a unified messaging/email/calendar API; LinkedIn is one of its channels alongside WhatsApp, Instagram, Messenger, Telegram, and X.

**What it offers**
- **Hosted auth**: a "Hosted Auth Wizard" — one API call generates a temporary link that redirects the end user to Unipile's hosted connect flow; a webhook can notify your backend when the account finishes connecting. [Unipile docs via search snippet](https://developer.unipile.com/docs/hosted-auth)
- **Messaging API**: conversation sync, message sending, invitation workflows (send a connection request with a note), and related account activity — positioned for "LinkedIn messaging workflows inside your app." [Unipile — LinkedIn API](https://www.unipile.com/communication-api/messaging-api/linkedin-api/)
- **Chats/messages listing**: REST endpoints to list/sync chats and messages as part of the same messaging API surface. [Unipile — unified REST API](https://www.unipile.com/developper-rest-api/)
- **Webhooks for new messages**: a dedicated "New messages" webhook fires in real time for messages received or sent, available across LinkedIn, WhatsApp, Instagram, Messenger, Telegram, and X. [Unipile — New messages webhook](https://developer.unipile.com/docs/new-messages-webhook)
- **Sales Navigator search**: `POST https://{account_dsn}/api/v1/linkedin/search` supports People/Company/Post/Job search against LinkedIn Classic, Sales Navigator, or Recruiter, selected via an `api` parameter (`classic` / `sales_navigator` / `recruiter`), with cursor-based pagination and a required `account_id` query param — access to each mode is gated by your Unipile subscription tier. [Unipile — Sales Navigator Search API](https://www.unipile.com/sales-navigator-search-api-key-features-editors-need-to-know/); [API reference](https://developer.unipile.com/reference/linkedincontroller_search)
- **Profile retrieval**: covered under the same LinkedIn API surface (profile + search-result extraction endpoints); exact response schema not independently verified in this pass — unverified (indirect). [Unipile — Extract LinkedIn Search Result API](https://www.unipile.com/extract-linkedin-search-result-api-best-practises/)
- **Rate limits**: Unipile itself imposes no artificial rate limit or usage fee; it passes through LinkedIn's own limits and relays LinkedIn's rate-limit headers/quota errors (e.g., `422 / cannot_resend_yet` when an invite can't be resent) so callers can back off gracefully. For a paid/active LinkedIn account, Unipile's own guidance is roughly 80–100 invitations/day (~200/week with a note up to 300 characters), with a documented recommendation to send only 10–50 invitation or message requests per day and randomize timing (not fixed hourly polling) to avoid automation-pattern detection. One invitation-withdrawal pass per week is allowed, only on invites ≥14 days old. Free (non-Premium) accounts are far more restricted — roughly 5 invites/month with a note, or ~15/week without one for accounts with some history. [Unipile — LinkedIn API doc](https://www.unipile.com/linkedin-api-documentation-integration-with-unipile/); [Unipile — Send Invitations via API](https://www.unipile.com/send-invitations-using-linkedin-api-from-your-software-application/); [Provider Limits and Restrictions](https://developer.unipile.com/docs/provider-limits-and-restrictions)
- **Base URL / auth**: each Unipile account gets a dedicated subdomain ("DSN", e.g. `apiX.unipile.com`) shown in the dashboard; requests go to `https://{your_dsn}/api/v1/...` (e.g. `.../api/v1/accounts`). Auth is via either an `X-API-KEY: <token>` header or `Authorization: Bearer <token>`, with the token created under Dashboard → Access Tokens / API Keys. `account_id` (returned when an account is first connected) is required on subsequent calls. Unverified against the primary docs page directly (proxy-blocked) — reconstructed from search snippets and the Node SDK repo. [unipile-node-sdk (GitHub)](https://github.com/unipile/unipile-node-sdk); [dltHub — Unipile source docs](https://dlthub.com/context/source/unipile)

**Pricing**: postpaid, per connected account, no usage/message fees on top. Base tier is ~$55/mo (49 EUR) for up to 10 linked accounts, then per-account rates step down with volume: ~$5.50/account (11–50), ~$5.00 (51–200), ~$4.50 (201–1,000), ~$4.00 (1,001–5,000), ~$3.50 beyond 5,000 — bands above 50 accounts reportedly move to sales-quoted volume pricing on the current pricing page. Billing is based on the peak number of connected accounts during the period. A 7-day free trial is offered, no card required. "Account" = one connected service (one LinkedIn login = one account), not one seat. [Unipile LinkedIn API pricing 2026](https://bereach.ai/tool-comparison/unipile-linkedin-api-pricing); [Unipile Pricing 2026 (TMB)](https://thatmarketingbuddy.com/pricing/unipile); [Unipile Review 2026 (Salesforge)](https://www.salesforge.ai/blog/unipile-review)

## 2. LinkedIn limits and policy (2026)

- **Weekly connection request limit**: not officially published by LinkedIn; widely observed by vendors/tools at roughly **100/week for free and Premium accounts**, with Sales Navigator accounts often reported higher (~150–200/week). The limit is dynamic per-account (acceptance rate, pending invites, account age, spam reports) and appears to reset on a rolling 7-day window from your first send of the cycle, not a fixed calendar day. [Cleverly](https://www.cleverly.co/blog/bypass-linkedin-weekly-invitation-limit); [PhantomBuster — Connection Request Limits](https://phantombuster.com/blog/social-selling/linkedin-connection-request-limit/); [Unipile — Send Invitations](https://www.unipile.com/send-invitations-using-linkedin-api-from-your-software-application/) (reports ~80–100/day, ~200/week for paid active accounts)
- **Daily message guidance (vendor consensus)**: keep to roughly **10–50 outbound requests/messages per day** per account, randomized timing rather than fixed schedules, to avoid pattern-based automation detection. [Unipile — LinkedIn API doc](https://www.unipile.com/linkedin-api-documentation-integration-with-unipile/)
- **User Agreement automation clause**: LinkedIn's User Agreement Section 8.2 prohibits developing, supporting, or using "software, devices, scripts, robots or any other means or processes ... to scrape the Services or otherwise copy profiles and other data," and separately prohibits using bots/automated means to access the Services, add/download contacts, or send/redirect messages; §8.2(4) further prohibits using content obtained "directly or through third parties (such as search tools or data aggregators)" without consent. Violation risk is account restriction or termination. [LinkedIn Help — Prohibited software and extensions](https://www.linkedin.com/help/linkedin/answer/a1341387)
- **What triggers restrictions**: fixed/robotic timing patterns, sudden spikes in daily/weekly volume, low connection-acceptance rate, high spam-report rate, and — per case law context — third-party scraping/data-aggregation flagged under the same clause (see the LinkedIn v. hiQ / LinkedIn v. Proxycurl line of enforcement). Proxycurl (a LinkedIn data-scraping API) was sued by LinkedIn in Jan 2025 over alleged fake-account scraping and shut down permanently on 2025-07-04 following a permanent injunction — direct evidence LinkedIn actively litigates against unauthorized scraping/automation vendors, not just individual accounts. [Metaverse Law — hiQ v. LinkedIn](https://www.metaverselaw.com/hiq-v-linkedin-user-agreements-in-the-age-of-data-scraping/); [StartupHub.ai — Proxycurl shuts down](https://www.startuphub.ai/ai-news/startup-news/2025/the-1-linkedin-scraping-startup-proxycurl-shuts-down)
- **Warm-up practices vendors recommend**: for a brand-new account, spend 3–4 weeks building activity manually (complete profile, 50–100 organic connections) before turning on any automation; when automation starts, begin at roughly 5–10 connection requests/day and ramp to 30–40/day over 4–6 weeks, capping period-over-period increases at ~30–40%; some guides recommend an even slower 6–8 week ramp for brand-new accounts, starting at ~10% of eventual target volume. Maintain a >70% acceptance rate as a health signal. [PhantomBuster — LinkedIn warm-up timeline](https://phantombuster.com/blog/linkedin-automation/linkedin-warm-up-timeline/); [ReactIn — Warm up a LinkedIn account](https://www.reactin.io/blog/warm-up-linkedin-account)
- **Sales Navigator seat price**: **Sales Navigator Core is $119.99/seat/month billed monthly, or ~$89.99/seat/month billed annually (~$1,079.88/year)**. [Overloop — Sales Navigator Pricing 2026](https://overloop.com/blog/linkedin-sales-navigator-pricing); [Cleanlist — Sales Navigator Pricing Guide](https://www.cleanlist.ai/blog/2026-05-08-linkedin-sales-navigator-pricing-guide)

## 4. Intent signals

**Observable directly on LinkedIn** (via the member's own account/notifications, no third-party data needed):
- **Profile views**: LinkedIn notifies users when someone views their profile (unless the viewer used Private Mode, which anonymizes as "LinkedIn Member"). Free accounts see the last 5 viewers by name (90-day window); Premium/Sales Navigator sees the full viewer list further back (~365 days). This is a native, first-party signal available only to the profile owner, not something a third party can pull for a target list. [PowerIn — Who Viewed My LinkedIn Profile](https://www.powerin.io/blog/who-viewed-my-linkedin-profile); [Salesrobot — LinkedIn Profile Views](https://www.salesrobot.co/blogs/linkedin-profile-views)
- **Post engagement**: likes/comments/reposts on a target's posts are visible to anyone viewing the post — directly observable, no scraping needed if pulled through an authorized API session (e.g., via a connected-account API like Unipile) rather than third-party scraping.
- **Job change**: visible on-profile once the member updates their LinkedIn profile (new title/company) — directly observable but lagging (depends on the person updating LinkedIn) and requires either manual browsing or an authorized API call per profile, not a bulk feed.

**Needs third-party data** (LinkedIn does not surface these as a bulk, queryable feed):
- **Hiring signals / job postings**: aggregated by providers reading job-posting and public web signals (e.g., PredictLeads, LoneScale, Crustdata's Watcher API).
- **Funding events**: aggregated by data providers (e.g., Crustdata, Clay-integrated sources) that append updated headcount/investor data when a company raises.
- **Bulk/real-time job-change tracking**: providers like PredictLeads and LoneScale explicitly sell "job change" and "hiring intent" as a monitored feed/webhook rather than a one-off profile check.

## 5. CRM and calendar integration facts

- **HubSpot OAuth scopes**: HubSpot's OAuth model ties each API endpoint to a specific granular scope string (format `crm.objects.<object>.read` / `.write`, e.g. `crm.objects.contacts.read`, `crm.objects.contacts.write`, `crm.objects.companies.read/write`, `crm.objects.deals.read/write`). Engagements (calls, emails, meetings, notes) have their own dedicated Engagement APIs/scopes (e.g. meetings-related scope errors reference a `meetings-read`-style scope in HubSpot's community forum). The authoritative, complete scope list lives at developers.hubspot.com (blocked by proxy this session) — treat exact scope strings for meetings/engagements as **unverified** pending direct confirmation; the object-CRUD scope pattern (`crm.objects.*.read/write`) is corroborated by multiple third-party integration docs (Airbyte, Prismatic, Scalekit). [Airbyte — HubSpot connector](https://docs.airbyte.com/integrations/sources/hubspot); [HubSpot Community — meetings-read scope](https://community.hubspot.com/t5/APIs-Integrations/meetings-read-scope-error/m-p/1255883)
- **Salesforce Connected App basics**: a Connected App is registered in Salesforce Setup to get OAuth-enabled access; the "Consumer Key" = `client_id` and "Consumer Secret" = `client_secret` (shown/revealed in the Connected App's API settings). Scopes are assigned at Connected App configuration time and included with issued OAuth tokens; common scopes include `full` (all data accessible to the logged-in user) and `offline_access` (issues a refresh token for later use without re-prompting). A Client Credentials flow can authenticate using only Consumer Key + Secret (no username/password/security token) for server-to-server integration. [Salesforce Help — OAuth Tokens and Scopes](https://help.salesforce.com/s/articleView?id=xcloud.remoteaccess_oauth_tokens_scopes.htm&language=en_US&type=5) (indirect — page itself blocked by proxy, summarized from search snippet); [ZappySys — Register Salesforce App](https://zappysys.com/blog/register-salesforce-app-obtain-client-id-secret-oauth-api-call/)
- **Google Calendar freebusy API shape**: `POST` to the `freebusy.query` endpoint with a JSON body of `{ timeMin, timeMax, timeZone (optional, default UTC), groupExpansionMax (≤100), calendarExpansionMax (≤50), items: [{ id: "<calendarId>" }, ...] }`; the response returns a `calendars` map keyed by calendar ID, each containing a `busy` array of `{start, end}` RFC3339 datetime blocks. This is the right primitive for checking a prospect/rep's open slots before proposing meeting times without needing full calendar read access. [Google for Developers — Freebusy: query](https://developers.google.com/workspace/calendar/api/v3/reference/freebusy/query) (indirect — direct fetch blocked by proxy, summarized from search snippet); [Nylas — Google Calendar Free/Busy guide](https://cli.nylas.com/guides/google-calendar-api-free-busy)
- **Cal.com API availability**: Cal.com has a public API v2 (v1 was fully sunset/removed as of 2026-04-08 — must use v2 and pass the `cal-api-version` header or requests default to an older version). API v2 covers bookings (create/get/list) and availability (create/find/edit/remove). Free/self-hosted users get read/write API access; hosted Platform API access is metered by booking volume rather than seats, with a free "Platform Starter" tier for prototyping (capacity for ~25 bookings) and paid Platform tiers starting ~$299/mo (Cal.ai-branded reference point) with per-booking overages ($0.50–$0.99 depending on tier). Teams/Org/Enterprise plans get the hosted API v2 bundled. [Cal.com Docs — API v2 Introduction](https://cal.com/docs/api-reference/v2/introduction); [Cal.com Docs — v1→v2 migration](https://cal.com/docs/api-reference/v2/v1-v2-differences); [CloudTalk — Cal.ai Pricing 2026](https://www.cloudtalk.io/cal-ai-pricing/)

## 6. Key takeaways

1. Unipile is a viable single integration point for LinkedIn connect/message/search — it exposes invitations-with-note, chat/message sync, new-message webhooks, and a unified Classic/Sales-Navigator/Recruiter search endpoint, all under one per-account price (~$5–$5.50/account/mo at our likely early volume, plus a $55/mo floor). [Unipile pricing](https://bereach.ai/tool-comparison/unipile-linkedin-api-pricing)
2. Unipile enforces no artificial rate limit of its own — it passes LinkedIn's real limits straight through and relays 422-style quota errors, so our Targeting/Reply Agents must implement the pacing logic (10–50 actions/day, randomized) rather than relying on the API to protect us. [Unipile docs](https://www.unipile.com/linkedin-api-documentation-integration-with-unipile/)
3. LinkedIn's weekly connection cap (~100/week typical, higher with Sales Navigator) is unpublished and adaptive — our onboarding flow needs a conservative default cadence and per-account backoff, not a hardcoded number.
4. The User Agreement's §8.2 automation/scraping prohibition is broad enough to cover third-party-obtained data too (§8.2(4)) — this reinforces going through an authorized, connected-account API (Unipile-style) rather than any scraping path, and explains why Proxycurl no longer exists as an option.
5. Proxycurl's 2025 shutdown (LinkedIn lawsuit → permanent injunction) is a hard signal: do not build our intent/enrichment layer on LinkedIn-profile scraping APIs — lean on job-posting/funding-based third-party providers (PredictLeads, Crustdata, Clay) instead, which infer signals from public web/company data rather than scraping LinkedIn directly.
6. CoPilot AI's real price point is $298–$398/mo per seat once the mandatory Sales Navigator add-on is included — this is materially higher than Dripify/Expandi/HeyReach and gives us room to underprice while still matching AI-reply functionality. [SalesRobot — CoPilot AI Review](https://www.salesrobot.co/blogs/copilot-ai-review)
7. Sales Navigator Core is $119.99/mo list ($89.99/mo annual) — if we require or resell it, that's a meaningful pass-through cost on top of our own subscription and should be reflected explicitly in pricing/positioning against CoPilot AI. [Sales Navigator Pricing](https://overloop.com/blog/linkedin-sales-navigator-pricing)
8. HeyReach's public API/webhook design (typed events like `CONNECTION_REQUEST_ACCEPTED`, `MESSAGE_REPLY_RECEIVED`) is a good reference model for our own event schema, even though we'll build on Unipile rather than HeyReach.
9. Account warm-up is a real, vendor-consistent practice (3–6 weeks manual activity before automation, then a 4–6 week ramp) — our onboarding UX should encode this as a guided warm-up flow, not leave it to user judgment.
10. Google Calendar's `freebusy.query` and Cal.com's v2 API are both lightweight enough to support "propose a time" in the Reply Agent without requiring full calendar-write scopes initially — start with freebusy read + Cal.com booking-link handoff before building two-way calendar write.
